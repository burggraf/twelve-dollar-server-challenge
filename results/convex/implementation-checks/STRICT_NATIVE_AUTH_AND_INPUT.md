## Native request validation

Native HTTP actions perform fresh WebCrypto HS256 key import and signature verification for **each request**. Tests include a genuine signature reaching body validation, payload tampering rejected, then genuine acceptance again, so an implementation rejecting every token cannot pass. Expiry, algorithm, `nbf`, signed positive-signed64 decimal-string subject and username type are checked. Authentication precedes body or like-ID validation.

Fatal UTF-8 decoding, malformed JSON, lone surrogates in nested keys/strings, nonfinite parsed numbers, ECMAScript trimming and the 500-codepoint boundary are covered. The pure helper adapts the existing Supabase contract without its Supabase-specific bridge token. There is no application-side PostgreSQL/SQLite driver, verification/result/response cache, like counter, new dependency/server or native limit increase. The existing native result-cache setting remains zero; identical-query reexecution was rechecked. Ordinary native database/index/module caches remain enabled.
